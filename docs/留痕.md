# 调用留痕

[返回首页](../README.md) · [文档导航](README.md) · [数据位置](数据.md)

模型的浏览器工具调用与页面跳转会追加到 `audit/YYYY-MM-DD.jsonl`，便于查看执行过哪些动作、从哪里跳到哪里，以及是否出错。

## 记录哪些内容

日志包含时间、工具名、参数摘要、成功或错误、耗时、浏览器模式与前后 URL。长字段会截断并标注；这份日志用于追溯动作，不是完整页面或对话录像。

`browser_type` 向已识别的密码字段输入时，日志保留字段、长度和摘要，不保留输入原文。键名命中 password、token、cookie 等敏感项时也会脱敏。

**普通输入、URL、错误与结果摘要仍可能包含页面内容。** 脱敏按字段和键名判断，不能保证所有敏感信息都被识别；直接通过页面脚本赋值也不等同于密码输入工具的处理。截图本身不由这套日志脱敏机制遮盖。

## 如何核对链

```powershell
npm run audit:check
```

也可以给校验工具指定某个日志文件或目录：

```powershell
node tools/verify-audit-chain.mjs D:\backup\browser-audit
```

没有日志时可能跳过；发现链断裂会报告位置。哈希链可发现单行改动或缺失，但拥有完整写权限的人能够重算链，不能把它当作不可篡改证据。

历史脱敏修复与链尾处理记录保留在[历史说明](历史.md)中。检查代码的离线测试与检查真实日志是不同动作，报告时应明确使用了哪一份数据。
