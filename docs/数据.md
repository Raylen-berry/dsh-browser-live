# 数据、下载与换机

## 数据位置

默认目录为 `DSH_HOME/dsh-browser-live/`。未设置 `DSH_HOME` 时使用当前用户主目录下的 `.dsh`；实际 Desktop 数据根以宿主运行环境为准。

| 文件或目录 | 保存什么 |
| --- | --- |
| `settings.json` | 画质、尺寸、启动参数、代理与浏览器模式 |
| `state.json` | 运行与启动兼容状态 |
| `bridge.json` | 用户浏览器桥的端口和连接 token |
| `chrome-profile-*` | 独立浏览器的登录态；按程序区分 profile，旧版也可能有 `chrome-profile/` |
| `downloads/` | 独立实例下载的文件 |
| `shots/` | 浏览器截图 |
| `audit/` | 按日追加的调用和跳转留痕，见[留痕](留痕.md) |

日常 Chrome／Edge 的登录态仍由该浏览器管理；扩展连接不会将其整份 profile 复制进插件目录。

## 下载与截图

独立实例的观察窗可通过下载链接取回 `downloads/` 中的文件。日常浏览器模式通过扩展查询下载元信息，需「允许操作」开启；不会暴露本地文件路径，也不等于独立实例的文件取回入口。

每次保存截图后自动检查：`shots/` 保留最近 200 张且仍在 7 天内的 PNG，超额或过期截图移到 **`DSH_HOME/dsh-cache-control/recycle/`**。

回收只移动，不永久删除、不释放空间；该目录由「会话策略」插件的存储页管理，或由你手动整理。需要保留的截图基准应放到单独的固定目录，避免依赖自动回收的 `shots/`。

## 备份设置与换机

在仓库目录可以导出或导入设置：

```powershell
node tools/settings.mjs export --out D:\bl-settings.json
node tools/settings.mjs import D:\bl-settings.json
```

导入不带 `--yes` 先预览，确认后再添加 `--yes` 执行；工具会在覆盖前备份设置。路径是示例，应换成自己的文件位置。

设置导出不包含扩展安装、桥 token、登录态、下载、截图或留痕。换机后重新准备浏览器，核对代理和程序路径；需要接入日常浏览器时，重新加载扩展并连接新机器的桥。

保留下载、截图和留痕需要分别备份相应目录。关闭独立浏览器不会删除其 profile；需要重新登录时，使用新的独立配置或自行管理旧 profile。
